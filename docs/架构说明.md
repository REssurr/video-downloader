# 架构说明

一句话：**一个 Electron 进程，里面跑一个只监听回环地址的 HTTP 服务**；界面是这个服务的一个页面，浏览器扩展是这个服务的另一个客户端，下载引擎和服务同进程。

```
┌─────────────────────────── Electron 主进程 ───────────────────────────┐
│                                                                        │
│  托盘 / 窗口（壳，src/electron/main.ts）                                │
│        │                                                               │
│        │ startHostServer()                                             │
│        ▼                                                               │
│  ┌────────────────────────── 本机 HTTP 服务 ──────────────────────────┐ │
│  │  127.0.0.1:47821（被占则 47822…47830）                             │ │
│  │                                                                   │ │
│  │  GET  /                  面板页面（web/index.html）                │ │
│  │  GET  /app.js            面板脚本（React，esbuild 打包）            │ │
│  │  POST /video-downloader/api/<method>   JSON 接口                  │ │
│  │  POST /video-downloader/upload       扩展推来的媒体字节            │ │
│  │  WS   /video-downloader/ws/events    面板的进度推送（只下行）       │ │
│  │  WS   /video-downloader/ext/ws       浏览器扩展的控制通道          │ │
│  └───────────────────────────────────────────────────────────────────┘ │
│        │                          │                                    │
│        ▼                          ▼                                    │
│   下载引擎（src/download.ts）   扩展通道（src/host/extension-hub.ts）    │
│   · 并发队列                    · hello/welcome 握手                   │
│   · 直连载体 / 扩展载体          · command(request/response, 带超时)    │
│   · 断点续传、原子改名            · 标签页跟踪、主动通知                │
│   · ffmpeg 合并（src/mux.ts）                                         │
└────────────────────────────────────────────────────────────────────────┘
         ▲                                          ▲
         │ HTTP（相对路径）                          │ WS + 上传
         │                                          │
   ┌─────┴─────┐                            ┌───────┴────────┐
   │  面板窗口  │                            │ Chrome/Edge 扩展│
   └───────────┘                            └────────────────┘
```

## 为什么界面从 `http://127.0.0.1:<port>/` 加载

面板要能直接用相对路径调 `/video-downloader/api/...`，唯一的前提是**页面自己就是这个服务的源**。用 `file://` 加载的话，相对的 API 路径和 `location.origin` 都不成立，还得额外放开 `file://` 的跨源限制。代价是面板本身成了"网页"，所以 Origin 校验必须认真做（见下）。

## 两条 WebSocket，方向相反

| 通道 | 谁连 | 谁发消息 | 用途 |
| --- | --- | --- | --- |
| `/video-downloader/ws/events` | 面板 | 只有服务端发 | 任务进度、配置变更、扩展状态；客户端断开后靠 HTTP 轮询也能活 |
| `/video-downloader/ext/ws` | 扩展 background | 双向 | 握手、命令（抓页面/开标签/探媒体）、扩展主动上报标签页与事件 |

扩展侧的 `background.js` 是**唯一**连这个 WS 的客户端；它启动后在 47821–47830 范围内逐个试连，连上后不会再换端口。所以本程序必须保持运行，扩展才连得上——这也是"关窗口缩到托盘、不退出进程"的原因。

## 两条下载载体（同一条队列）

| 载体 | 字节从哪来 | 什么时候用 |
| --- | --- | --- |
| `direct` | 本程序自己发 HTTP 请求（走系统代理设置） | 默认；直链、公开 mp4 |
| `guest` | 浏览器扩展用**浏览器自己的 cookie / IP / TLS** 取字节，再分块 POST 到 `/upload` | 站点对非浏览器客户端返回 403 时（挑战、防盗链、登录态） |

`guest` 的每次任务在创建时就生成一个随机 token，页面/扩展只能凭这个 token 推字节；任务一进入终态（完成/失败/取消/跳过）token 立刻作废，排队中被取消也一样——否则一条迟到的推送会永远等一个不会再来的接收方。

## 断点续传的规则

`.part` 文件存在时才会续传，而且必须同时满足：

1. 请求带 `Range`，并且（若能拿到）带 `If-Range` 回显上次的 `ETag`/`Last-Modified`；
2. 响应是 `206`，且 `Content-Range` 的起点**等于**磁盘上的字节数；
3. 响应里的 `ETag`/`Last-Modified` 与上次记录（`.part.meta`）不冲突。

任何一条不满足就丢掉偏移、从头重下。宁可多下一次，也不要拼出一个"长度对得上但内容是两次的混合体"的文件。文件只有在完整后才改名成最终名字，所以**目录里出现最终文件名 = 这个文件是完整的**。

## 扩展做什么、不做什么

- 做：读页面 DOM（content script）、跑站点适配器（目前只有 B 站：用页面自己的登录态调站点接口拿到整份 mp4 或 DASH 轨）、把找到的候选地址交回本程序、按本程序给的 token 取字节。
- 不做：判断"这个地址能不能下"、挑清晰度、合并、决定文件名——这些全在本程序里（`src/probe/policy.ts`、`src/client/picker-model.ts`、`src/download.ts`），这样规则只有一份，也测得到。

## 安全边界

- 只监听 `127.0.0.1`，外部网络访问不到。
- `/api` 与两条 WS 都校验 `Origin`：只接受本服务自己的源、`chrome-extension://`，以及没有 `Origin` 的本机原生客户端。`Origin: null`（沙箱 iframe、`data:` 页面）一律拒绝。
- `/upload` 除 Origin 外还要求任务 token，token 一次性、只对一条任务有效。
- 面板的 HTML 带 CSP，禁止内联脚本与外部源。
- 配置（含下载目录）只存在本机 `%APPDATA%\video-downloader\config.json`，不上传任何地方。

## 配置与遗留兼容

首次启动时若本机存在旧插件的配置（`~/.dsh/video-downloader/config.json`），会**只读**地继承一次下载目录等设置，然后写进自己的配置。之后与插件再无关系，插件目录永远不被写入。
